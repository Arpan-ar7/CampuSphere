# 1. Getting started

[← Back to notes](<README.md>)

## What you need

- **Node.js 20.9 or newer** (check with `node -v`). Next.js 16 needs it; it's also written in [package.json](<../frontend/package.json>) under `engines`.
- npm (comes with Node.js).

## Run the app

```powershell
cd frontend
npm install
npm run dev
```

Open **http://localhost:3000**. In demo mode, **any email and password logs you in**.

## Commands

All are defined in [frontend/package.json](<../frontend/package.json>) → `scripts`.

| Command | What it does | When to use it |
|---|---|---|
| `npm run dev` | Starts the app with live reload (changes show instantly) | While coding |
| `npm run typecheck` | Checks all TypeScript types (`tsc --noEmit`) | After changing data shapes or props |
| `npm run lint` | Checks the code for mistakes with ESLint | Before committing |
| `npm run build` | Builds the optimised production version (also catches errors) | Before deploying |
| `npm start` | Runs the production version (after `build`) | To test production locally |
| `npm run check` | `typecheck` + `lint` + `build` together | Quick "is everything OK?" check |

## Settings (environment variables)

Settings that change between computers or servers live in a file called **`.env.local`** inside `frontend/`.
It is **not committed to git**. Copy the example to start:

```powershell
cd frontend
Copy-Item .env.example .env.local
```

The example file is [frontend/.env.example](<../frontend/.env.example>):

| Variable | Meaning |
|---|---|
| `NEXT_PUBLIC_USE_MOCK` | `true` = use the fake data in [mock/data.ts](<../frontend/src/mock/data.ts>). `false` = call the real backend |
| `NEXT_PUBLIC_API_URL` | Where the backend lives, e.g. `http://localhost:5000/api` |

> ⚠️ Anything starting with `NEXT_PUBLIC_` is **sent to the browser** and anyone can read it.
> Never put passwords, secret keys or tokens in these variables.

Restart `npm run dev` after changing `.env.local`.

## Project config files (in `frontend/`)

| File | What it is |
|---|---|
| [package.json](<../frontend/package.json>) | Project name, required Node version, commands, and the libraries we use |
| [package-lock.json](<../frontend/package-lock.json>) | Exact versions of every library (auto-generated, don't edit by hand) |
| [next.config.ts](<../frontend/next.config.ts>) | Next.js settings: **security headers**, Cache Components, Tailwind setup |
| [eslint.config.mjs](<../frontend/eslint.config.mjs>) | Code-checking rules (`npm run lint`) |
| [tsconfig.json](<../frontend/tsconfig.json>) | TypeScript settings (strict mode) + the `@/` shortcut so we write `@/components/...` instead of `../../../components/...` |
| `next-env.d.ts` | Generated by Next.js so TypeScript understands images, CSS and Next types (don't edit) |
| [.env.example](<../frontend/.env.example>) | Template for `.env.local` (settings) |
| [.gitignore](<../frontend/.gitignore>) | Files git should ignore (`node_modules`, `.next`, `.env.local`…) |
| [AGENTS.md](<../frontend/AGENTS.md>) | Note for AI coding tools: "read the Next.js 16 docs first" (added by Next.js) |
| [README.md](<../frontend/README.md>) | Short project readme with a folder map |

Generated folders you never edit: `node_modules/` (installed libraries) and `.next/` (build output).
